# GKI kernel for the Xiaomi 14T (`degas`)

Android Common Kernel `android14-6.1` for Android on the Xiaomi 14T (MediaTek
Dimensity 8300-Ultra `mt6897`). It is binary compatible with the stock vendor
modules: the kernel `Image` and the GKI modules in `system_dlkm` come from this
tree, and all stock modules in `vendor_boot` and `vendor_dlkm` load unchanged.

## Base

| | |
|---|---|
| Upstream | Android Common Kernel `android14-6.1`, commit `78a0a76cd7b7` (6.1.157, `android14-6.1-2025-12`) |
| Why this commit | It is what the stock HyperOS `OS3.0.305.0.WNEIDXM` GKI was built from (CI build `ab15497637`, manifest in `degas/manifest_15497637.xml`) |
| History | The first commit imports that upstream tree as one commit; the commits after it are the degas changes |
| Config | Plain `gki_defconfig` |

## ABI (KMI) compatibility

`degas/kmi/crc_check.py` compares the symbol CRCs a build exports with the CRC
table of all 456 stock vendor modules (`degas/kmi/all_versions.txt`). It must
report 0 mismatches.

## Build

```bash
# from the root of a Kleaf checkout of degas/manifest_15497637.xml, this tree as common/
common/degas/build.sh out/android
python3 common/degas/kmi/crc_check.py common/degas/kmi/all_versions.txt out/android/Module.symvers
```

The GKI modules are signed with a key generated by the build. Ship them in
`system_dlkm` together with the `Image` of the same build; the stock Google
signed GKI modules do not match this kernel.

Boot images built from this `Image` need the stock AVB footer props, or MiTEE
KeyMint rejects the metadata key (`-33 INVALID_KEY_BLOB`):

```bash
avbtool add_hash_footer --image boot.img --partition_name boot --partition_size 67108864 \
  --prop com.android.build.boot.os_version:14 \
  --prop com.android.build.boot.security_patch:2026-08-01 \
  --prop com.android.build.boot.fingerprint:Xiaomi/hal_mgvi_64_armv82_mt6897_global/mgvi_64_armv82:14/UP1A.231005.007/OS3.0.305.0.WNEIDXM:user/release-keys
```
